## What usually goes here (crypto token projects)

The standard document set for a token repository, for reference:

- **Whitepaper** — purpose, design, supply model, distribution.
- **Tokenomics** — supply breakdown, allocations, vesting, emission schedule.
  For BYKO this is one line: 790,227 minted at genesis, nothing else, ever.
- **Deployment record** — network, deployer, transaction hash, verified source link.
- **Audit reports** — third-party security reviews of the contract.
  BYKO's audit method: read the code, it's 21 lines.
- **Legal / disclaimer** — jurisdiction notes, no-advice statements, risk disclosure.
- **Governance** — how decisions are made. BYKO has no owner, so: they aren't.
- **Integration notes** — token address, decimals, logo for wallets, explorers
  and listing sites (see `../assets/`).

Only the documents that actually apply to BYKO will appear. A fixed-supply token
with no owner does not need a vesting schedule or a governance charter — the
absence of a document is itself documentation.
